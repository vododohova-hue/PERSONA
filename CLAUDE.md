# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Профиль владельца проекта
Полный профиль — в [profile.md](profile.md), прочитай его, чтобы понимать, для кого и зачем этот проект.

## Цель проекта
Это лендинг для привлечения клиентов — не портфолио и не блог. Задача страницы: убедить посетителя, что перед ним надёжный специалист 1С с 14+ годами опыта, и подтолкнуть его оставить заявку/написать.

## Структура репозитория
- [index.html](index.html) — единственная страница сайта: вся вёрстка, стили (в `<style>` в `<head>`) и контент лежат в одном файле.
- [images/](images/) — фотографии для секций (hero, портрет, карточки проектов, финальная цитата). [images/CREDITS.md](images/CREDITS.md) фиксирует источник и лицензию для каждой картинки.
- `profile.md`, `про-меня.md`, `проекты.md`, `факты.md` — исходные тексты-досье о владелице проекта (биография, опыт, проекты, факты). Это источник правды для контента `index.html`: при обновлении фактов на странице (даты, места работы, цифры) сверяйся с этими файлами и держи их синхронными.

Сборки, package.json и тестов в проекте нет — это статический HTML/CSS без зависимостей.

## Как проверить изменения
Открыть [index.html](index.html) напрямую в браузере (двойной клик или `file://`) — сервер не нужен, никакого рантайма нет.

## Тон и стиль
- Строго и статусно: сдержанный, профессиональный тон.
- Акцент на надёжность и опыт, а не на эмоции.
- Минимум маркетингового пафоса, никаких кричащих обещаний и превосходных степеней без подтверждения фактами.
- Дизайн — сдержанный, без ярких/игривых элементов, без лишней анимации и визуального шума.

## Ограничения — чего не делать
- Не тащить фреймворки и сборку (React, Vue, webpack и т.п.) — только чистые HTML/CSS/JS.
- Не добавлять бэкенд и базу данных — проект статический; формы обратной связи реализовывать через внешние сервисы (например, Telegram-бот, email-сервис, mailto).
- Не раздувать проект — это простой одностраничный лендинг, не плодить лишние страницы/разделы без явной необходимости.

## Изображения
- Новые изображения брать только со свободными лицензиями (например, через Openverse), как это сделано для текущих картинок.
- Для лицензий CC-BY / CC-BY-SA обязательно фиксировать автора и лицензию в [images/CREDITS.md](images/CREDITS.md) — так же, как оформлены существующие записи.
